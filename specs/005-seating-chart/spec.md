# Feature Specification: 婚宴座位安排（後台座位圖）

**Feature Branch**: `005-seating-chart`
**Created**: 2026-11-05
**Status**: Draft
**Input**: 根據「草悟廳 Banquet Hall」場地平面圖，在後台新增座位安排功能。圖中白底圓圈為可入座之桌（共 17 桌），每桌 10 人；主辦人需能將人名與人數加入各桌並調整。

## User Scenarios & Testing

### User Story 1 — 檢視會場座位圖（Priority: P1）

主辦人登入後台後，進入「座位安排」頁面，看到與場地平面圖相同配置的 17 張桌子（含舞台、柱子、入口作為參考），每桌顯示桌名與「已入座人數 / 10」，並以顏色區分空桌、未滿、已滿。

**Independent Test**: 開啟 `/admin/seating`，看到 17 張桌，位置與平面圖相符；上方統計顯示總座位 170、已安排人數。

### User Story 2 — 新增、修改、刪除桌上賓客（Priority: P1）

點選任一桌，開啟該桌明細面板：可輸入「姓名 + 人數（預設 1）+ 備註」加入該桌；可修改姓名、人數、備註；可刪除；可更改桌名（例如「主桌」、「新郎同事」）。

**Independent Test**: 點第 3 桌，新增「王小明 / 3 人」，桌面顯示 3/10；修改為 4 人後顯示 4/10；刪除後回到 0/10。

### User Story 3 — 調整座位（換桌）（Priority: P2）

主辦人可將某位賓客（組）移到另一桌；若目標桌剩餘座位不足則阻擋並提示。

**Independent Test**: 第 3 桌「王小明 4 人」換到第 5 桌，第 3 桌人數減少、第 5 桌增加；若第 5 桌已 8 人則提示「座位不足」且不移動。

### User Story 4 — 從 RSVP 名單快速加入（Priority: P2）

面板列出「已回覆參加、尚未安排座位」的 RSVP 賓客（人數 = 大人 + 小孩），可一鍵加入目前所選的桌。

**Independent Test**: 有一筆參加的 RSVP「李大華 大人 2 小孩 1」，在未安排列表出現；加入第 7 桌後，第 7 桌增加 3 人，該筆從未安排列表消失。

### User Story 5 — 匯出座位表（Priority: P3）

匯出 CSV（UTF-8 BOM，Excel 可開）：桌號、桌名、姓名、人數、備註，並附每桌小計。

### Edge Cases

- 單桌總人數超過 10 → 後端回傳 409 `TABLE_FULL`，前端顯示「此桌剩餘 N 位」。
- 人數須為 1–10 的整數；姓名 1–50 字。
- 桌號只允許 0–16：0 為主桌（舞台正前方，顯示「主桌」不顯示數字），1–16 由最左欄開始、每欄由上往下編號。
- RSVP 被刪除後，已安排的座位資料保留（僅失去連結）。

## Requirements

- **FR-001**: 系統 MUST 提供 17 張固定桌位（主桌 + 第 1–16 桌），每桌容量 10 人；桌位座標依場地平面圖固定於前端。
- **FR-002**: 系統 MUST 允許主辦人於每桌新增 / 修改 / 刪除座位紀錄（姓名、人數、備註）。
- **FR-003**: 系統 MUST 允許修改桌名（可留空，留空時顯示「第 N 桌」）。
- **FR-004**: 系統 MUST 允許將座位紀錄移至另一桌，並於後端驗證容量。
- **FR-005**: 系統 MUST 於後端阻擋任何使單桌超過 10 人的新增 / 修改。
- **FR-006**: 系統 SHOULD 列出已參加但未安排的 RSVP，並可一鍵加入。
- **FR-007**: 系統 SHOULD 提供 CSV 匯出。
- **FR-008**: 所有 API 需經 `adminAuth` 驗證。

## Success Criteria

- **SC-001**: 主辦人可在 1 分鐘內完成單桌 10 人的安排。
- **SC-002**: 手機（≥ 360px 寬）可完整操作，座位圖不需水平捲動。
