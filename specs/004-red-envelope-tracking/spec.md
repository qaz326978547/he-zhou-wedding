## 專案概覽

在婚禮現場（或婚禮前）提供一個賓客端頁面，讓協助收禮金的人員（接待或賓客本人）於交付紅包時，快速登記「姓名」與「紅包金額」。
主辦人可透過後台新頁面即時查看所有登記紀錄、紅包金額總計，並匯出成 Excel 方便對帳與保存。

---

## User Scenarios & Testing

### User Story 1 — 賓客端登記紅包（Priority: P1）

賓客（或協助收禮的接待人員）開啟 `/qr` 頁面，填寫姓名與紅包金額後送出，系統將資料儲存至後端。

**Why this priority**: 這是整個功能的資料來源；沒有登記就沒有後續的列表與總計可言，是 MVP 的核心。

**Independent Test**: 開啟 `/qr` 頁面，填寫姓名「王大明」與金額「3600」並送出，確認頁面顯示送出成功提示，且該筆資料出現在後台列表中。

**Acceptance Scenarios**:

1. **Given** 賓客開啟 `/qr` 頁面，**When** 頁面載入完成，**Then** MUST 顯示「姓名」與「紅包金額」兩個輸入欄位，以及送出按鈕。
2. **Given** 賓客填寫姓名與有效金額（正整數），**When** 點擊送出，**Then** 系統 MUST 將資料儲存並顯示送出成功的確認畫面（例如感謝訊息），欄位清空以便下一位賓客登記。
3. **Given** 賓客未填寫姓名或金額，**When** 點擊送出，**Then** MUST 在對應欄位顯示錯誤提示，表單不送出。
4. **Given** 賓客輸入非數字或 0 / 負數金額，**When** 點擊送出，**Then** MUST 顯示金額格式錯誤提示，表單不送出。
5. **Given** 賓客送出成功，**When** 送出請求因網路問題失敗，**Then** MUST 顯示錯誤提示並允許賓客重新送出，不遺失已填寫的內容。

---

### User Story 2 — 主辦人查看、管理紅包列表與總計（Priority: P2）

主辦人登入後台後，可在新頁面看到所有賓客登記的姓名與金額列表，看到全部金額的加總，並可修改或刪除登記錯誤的紀錄。

**Why this priority**: 主辦人需要即時掌握收禮進度與總金額，並能修正現場登記時的手誤（例如姓名打錯、金額輸入錯誤），是本功能對主辦人最直接的價值。

**Independent Test**: 登入後台並前往紅包登記頁面，確認列表顯示所有 `/qr` 頁面送出的紀錄，列表上方或下方顯示的總計金額等於所有紀錄金額加總；修改某筆金額後總計即時更新；刪除某筆後該筆從列表與總計中消失。

**Acceptance Scenarios**:

1. **Given** 主辦人已登入後台，**When** 進入紅包登記頁面，**Then** MUST 顯示所有登記紀錄，每筆包含：姓名、金額、登記時間。
2. **Given** 後台紅包登記頁面已載入資料，**When** 頁面渲染完成，**Then** MUST 在明顯位置顯示所有紀錄金額的加總（總金額）與總筆數。
3. **Given** 尚未登入，**When** 直接訪問後台紅包登記頁面路由，**Then** MUST 導向登入頁，不暴露任何紅包資料（沿用既有後台身份驗證機制）。
4. **Given** 尚無任何登記紀錄，**When** 主辦人進入頁面，**Then** MUST 顯示空狀態提示（例如「尚無紅包登記紀錄」），總金額顯示為 0。
5. **Given** 主辦人點擊某筆紀錄的「修改」，**When** 該列進入可編輯狀態並修改姓名或金額後儲存，**Then** 列表與總金額 MUST 立即反映更新後的數值。
6. **Given** 主辦人點擊某筆紀錄的「刪除」，**When** 確認刪除，**Then** 該筆紀錄 MUST 從資料庫、列表與總金額中永久移除。

---

### User Story 3 — 主辦人匯出 Excel（Priority: P3）

主辦人在紅包登記頁面點擊匯出按鈕，下載包含所有登記紀錄與總計的檔案，方便離線對帳與保存紀錄。

**Why this priority**: 匯出是列表功能的延伸價值，讓資料可離線保存與分享（例如給雙方家長核對），優先度低於「看得到資料」本身。

**Independent Test**: 在紅包登記頁面點擊「匯出 Excel」，確認下載的檔案可用 Excel 開啟，內容包含所有登記紀錄（姓名、金額、時間）與總計金額，中文字不亂碼。

**Acceptance Scenarios**:

1. **Given** 紅包登記頁面已顯示列表，**When** 主辦人點擊「匯出 Excel」，**Then** MUST 立即下載一個以目前列表資料為內容的檔案，用 Excel 開啟時中文姓名正確顯示、不亂碼。
2. **Given** 匯出的檔案，**When** 主辦人開啟檢視，**Then** 內容 MUST 包含每筆登記的姓名、金額、登記時間，以及總金額、總筆數的統計資訊。
3. **Given** 尚無任何登記紀錄，**When** 主辦人點擊「匯出 Excel」，**Then** MUST 仍可下載檔案，內容僅含欄位標題與總計為 0，不噴錯。

---

### Edge Cases

- 賓客同時（同一秒）大量送出資料（現場多人排隊登記），系統 MUST 正確儲存每一筆，不遺失或覆蓋資料。
- 賓客金額輸入極大數字（例如 99999999），系統 MUST 仍能正確儲存與加總，不溢位或顯示錯誤。
- 賓客姓名包含特殊字元或超長字串，系統 MUST 有合理長度限制並給予錯誤提示。
- 後台列表資料筆數很多（例如超過 200 筆）時，頁面 MUST 仍可正常瀏覽與匯出，列表載入與渲染時間 MUST 在 2 秒內完成。
- 主辦人在小螢幕（手機）瀏覽後台紅包頁面時，列表與總計 MUST 完整可讀，不需橫向捲動。

## Requirements

### Functional Requirements

#### FR-001 賓客端登記頁面
系統 MUST 在路由 `/qr` 提供公開頁面（無需登入），顯示「姓名」與「紅包金額」兩個必填欄位及送出按鈕。

#### FR-002 表單驗證
系統 MUST 驗證：姓名不可為空、金額必須為正整數（大於 0）；驗證失敗時 MUST 於對應欄位顯示錯誤提示，且不送出資料。

#### FR-003 資料儲存
賓客送出表單後，系統 MUST 將姓名、金額、送出時間儲存至後端資料庫；即使同一裝置連續送出多筆，MUST 全部保留（不覆蓋前一筆）。

#### FR-004 送出成功回饋
資料儲存成功後，系統 MUST 顯示送出成功的確認畫面或提示訊息，並清空表單以便下一位賓客繼續登記；儲存失敗時 MUST 顯示錯誤提示且不清空已填寫內容，允許重新送出。

#### FR-005 後台路由保護
新增的後台紅包登記頁面 MUST 沿用既有 `/admin` 身份驗證機制（未登入時導向 `/admin/login`，後端 API MUST 驗證有效 token，無效或過期回傳 401）。

#### FR-006 後台列表與統計
後台紅包登記頁面 MUST 顯示所有登記紀錄（姓名、金額、登記時間），並在列表上方顯示：總筆數、總金額（所有紀錄金額加總，即時依已載入資料計算）。系統 MUST NOT 對姓名進行重複比對或阻擋，所有提交的紀錄一律保留並計入加總。後台 MUST 提供從既有 RSVP 後台頁面前往紅包登記頁面的導覽入口，方便主辦人於同一後台體系內切換。

#### FR-007 修改紅包紀錄
主辦人 MUST 可修改任一筆紀錄的姓名與金額；修改介面比照既有 RSVP 後台 inline 編輯模式（該列欄位直接變為可編輯輸入框）；儲存後 MUST 立即更新列表顯示與總金額；金額修改後仍 MUST 符合正整數驗證規則。

#### FR-008 刪除紅包紀錄
主辦人 MUST 可刪除任一筆紀錄；刪除前 MUST 顯示確認對話框，確認後該筆紀錄 MUST 從資料庫永久移除，並同步更新列表與總金額。

#### FR-009 匯出 Excel
主辦人 MUST 可在後台紅包登記頁面點擊「匯出 Excel」，下載包含目前所有登記紀錄（姓名、金額、登記時間）與總計（總筆數、總金額）的檔案；檔案 MUST 可用 Excel 正常開啟，中文字元 MUST NOT 亂碼；檔名 MUST 包含匯出日期（例如 `紅包登記_YYYYMMDD`）。

### Key Entities

- **RedEnvelopeEntry（紅包登記紀錄）**：代表一筆賓客登記，包含姓名、金額（正整數，新台幣）、登記時間。與既有 `RSVPSubmission` 無關聯，為獨立資料。

## Success Criteria

### Measurable Outcomes

- **SC-001**：賓客在 `/qr` 頁面可於 30 秒內完成一筆姓名與金額的登記並送出成功。
- **SC-002**：主辦人登入後台後，5 秒內可看到最新的紅包登記列表與正確的總金額（與所有紀錄手動加總結果一致，誤差為 0）。
- **SC-003**：匯出的檔案 100% 可用 Excel 正常開啟並正確顯示中文姓名，總計金額與後台頁面顯示金額一致。
- **SC-004**：未登入狀態下嘗試存取後台紅包資料（頁面或 API）100% 被導向登入頁或回傳 401，不洩漏任何登記資料。
- **SC-005**：後台紅包登記頁面在 375px（手機）至 1440px（桌機）寬度範圍內完整可用，列表與總計文字不需橫向捲動即可讀取。
- **SC-006**：主辦人修改或刪除任一筆紀錄後，不需手動重新整理頁面，列表與總金額 MUST 立即反映最新結果。

## Assumptions

- `/qr` 頁面比照既有 RSVP 表單，為公開頁面，無需登入即可送出資料；不額外要求輸入電話或其他身份識別欄位，因為現場登記多由接待人員協助操作。
- 匯出檔案格式比照既有 RSVP 後台「匯出 CSV」模式（FR-A011，`specs/002-admin-dashboard/spec.md`），採用 UTF-8 BOM 的 CSV 格式以確保 Excel 開啟時中文不亂碼；使用者所稱「匯出 Excel」即指此種可被 Excel 開啟的格式，非要求產出原生 `.xlsx` 二進位檔案。
- 金額幣別固定為新台幣（TWD），不支援其他幣別；金額上限依資料庫整數型別約束（約 21 億），無需額外前端上限限制，實務婚禮紅包金額不會接近此範圍。
- 後台紅包登記頁面掛載於既有 `/admin` 身份驗證機制之下（沿用 `002-admin-dashboard` 的 JWT + localStorage 方案），不另外設計新的登入系統。
- v1 不需要防止惡意灌爆資料的複雜機制，僅需與現有 RSVP 表單相同等級的基本保護（例如 IP 速率限制），因為 `/qr` 網址不會公開宣傳，僅提供婚宴現場掃碼使用。
- 紅包登記資料與 RSVP 資料為兩個獨立資料表，不互相關聯比對（賓客登記紅包時不需要輸入與 RSVP 相同的姓名或電話）。

## Out of Scope（v1）

- 紅包金流串接（例如電子紅包、行動支付金流對接）；本功能僅為人工登記與記帳輔助工具。
- 賓客端查詢或修改自己已送出的登記紀錄。
- 依桌次、賓客類型（新郎/新娘親友）分類統計紅包金額。
- 後台角色權限分級（沿用既有兩位主辦人共用權限）。
